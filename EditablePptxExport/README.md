# AviUtl 1 → 編集可能PPTX（試作版 0.4.0）

AviUtlの現在のシーンを取得し、一定間隔のフレームをPowerPointのスライドにします。
拡張編集0.92では、手動でEXOを書き出す必要はありません。保存済みEXOの変換も可能です。
文字はテキストボックス、静止画像は個別の画像、背景・塗りつぶし四角形は編集可能な図形として保存します。
文字のコピー・検索・編集が可能です。OCRは使用しません。

既存のPNG出力プラグインや既存のソリューションには変更を加えていません。
このフォルダだけで動作する変換ツールと、任意で利用できるAviUtl起動用プラグインです。

## すぐ試す

この作業環境では依存関係を .venv に準備済みです。

1. launch.cmd をダブルクリックします。
2. 入力に examples/sample.exo を選びます。
3. 保存先に新しいPPTX名を指定し、「PPTXに変換」を押します。
4. PowerPointで開いて、文字を選択・編集できることを確認します。

examples/sample.pptx は生成済みの2ページのサンプルです。
examples/calibration.png は位置・回転・透明度確認用の画像です。

自分の作品は、下記のAviUtlメニューから取得できます。
launch.cmdだけを使う場合は、拡張編集の「オブジェクトファイルのエクスポート」で
対象をEXOに保存し、そのEXOを選択します。
GUIにAUPやPNGを直接入力することはできません。画像の元ファイルも必要です。

## AviUtlのメニューから起動する（任意）

1. AviUtlを終了してから、このフォルダの EditablePptxExport.auf を、
   aviutl.exe と同じフォルダにある plugins フォルダ直下へコピーします。
   旧版を配置済みの場合は置き換えます。
   既存の IntervalPngExport.auo はそのままにします。
2. AviUtlを起動し直します。
3. 「ファイル」→「エクスポート」→「現在のシーンから編集可能PPTXを作成」を選びます。
   項目が無効になっている場合は、編集対象のプロジェクトや画像を開いてください。
4. ファイル選択が出たら、このツールの gui.py を指定します。
5. 現在のシーンを取得済みの変換画面が開きます。
   保存先・フレーム間隔などを確認し、「PPTXに変換」を押します。

**0.2.0では .auf の差し替えが必要です。以前の .auf では自動取得できません。**
現在開いているシーン全体が対象です。オブジェクトの選択は不要です。
未保存の編集も取得でき、AUPの保存やタイムラインの変更は行いません。
取得後に編集した内容を反映する場合は、画面を閉じてメニューから取得し直してください。
ツールの場所はAviUtl起動中だけ記憶します。
AviUtl 2用ではありません。32ビット（x86）でビルド済みです。
AviUtl 1.10＋拡張編集0.92の独立した検証環境で、自動取得とGUI起動を確認済みです。

自動取得は、拡張編集0.92の内部EXO出力関数を使用します。
バージョンとDLL構造を確認し、対応外の拡張編集では実行を停止します。
全シーンの一括取得やシーン参照の展開には対応していません。
EXOはこのツールの .runtime/snapshots 内に一時保存し、変換画面の終了時に削除します。
強制終了した場合は一時データが残ることがあります。
保存先はAUPと同じフォルダの「作品名_editable.pptx」を提案します。
AUPが未保存の場合はAviUtlの作業フォルダを提案します。必要に応じて変更してください。
同名のPPTX・レポートがある場合は連番を付けます。

0.1.0では設定ウィンドウを作らない構成でWM_FILTER_INITからメニュー追加を試みていたため、
メニューが表示されない症状を確認しました。0.1.1ではSDK標準のエクスポートメニュー登録に変更しました。
「プラグイン出力」や「設定」メニューではなく、上記の「エクスポート」を確認してください。

## 引用・脚注番号の自動更新（0.4.0）

AviUtl 1.10＋拡張編集0.92用です。
AviUtlを終了し、このフォルダの **CitationManager.auf** と更新版 **EditablePptxExport.auf** を
plugins直下に配置してから起動し直します。

1. 「ファイル」→「エクスポート」→「論文の引用・脚注番号を更新」を選びます。
   初回に場所を聞かれたら、このフォルダの gui.py を指定します。手動のEXO出力は不要です。
2. 「文献の登録」タブで、論文キーと脚注に表示する書誌情報を入力し、「追加 / 変更」を押します。
   例えばキー smith2024、書誌情報「著者名, 論文タイトル, 会議名, 2024.」です。
3. 「引用文章」タブで対象の文章を選び、引用キーを入力します。
   AviUtlの通常のテキスト入力欄で、最初からキーを書いておくこともできます。
4. 「番号をプレビュー」で確認し、「引用番号をAviUtlに反映」を押します。
5. AUPを保存します。スライドや論文の順番を変えたら、管理画面を開き直して再度反映します。

| 入力する記法 | 表示例 |
|---|---|
| \cite{smith2024} | [1] |
| \cite{smith2024,tanaka2025} | [1, 2] |
| \ref{smith2024} | [1] 著者名, 論文タイトル, 会議名, 2024. |
| \bibliography | 使用した文献を番号順に改行して表示 |

現在のシーンのテキスト全体を調べ、最初の \cite の開始フレーム順に採番します。
同じ開始フレームではレイヤー順、その後はオブジェクト順と文章内の出現順を使います。
同じ論文を何度引用しても番号は共通です。
\refだけに登場する論文は、本文で引用した論文の後に番号を付けます。
登録しただけで引用していない論文は、文献一覧に含めません。

0.4.0では、引用キー・元の文章・書誌情報を別の **作品名.citations.json** に保存します。
AviUtlのテキストには表示する文章だけが入り、長い管理用コメントは追加しません。
旧版でコメントが入った作品は、管理画面を開いて「引用番号をAviUtlに反映」を押すと移行できます。
**AUPと.citations.jsonを一緒に保管・移動してください。** EXOを別フォルダへ移す場合も管理ファイルが必要です。
文献登録の.references.jsonとは別のファイルです。管理画面下部に保存先を表示します。
まずAUPを保存してから引用を反映することを推奨します。
未保存作品では references.citations.json をAviUtlの作業フォルダに保存します。
未保存からAUPを保存した場合や別名保存した場合は、次回の管理画面で「引用管理ファイルを開く」から以前のファイルを指定してください。
必要に応じて、AUPと同じフォルダへ作品名.citations.jsonとしてコピーしてください。

管理画面では元の引用キー付き文章を編集できます。
AviUtlやアルティメットの編集欄では、普通の文章だけを表示します。
移動や同じ文章の複製後も、変更されていない表示文章を照合して引用キーを復元します。
同じ表示文章が異なる引用テンプレートに対応する場合は、自動で推測せず停止します。
反映後の文章をAviUtl側で変更した場合は、元の文章との対応が失われることがあります。
引用を含む文章の編集は管理画面で行うか、「引用キーに戻す」を押してから通常の編集欄で編集してください。

更新は拡張編集のUndoに記録します。拡張編集ウィンドウでCtrl+Zを押すと一括で戻せます。
管理画面を開いた後に移動・文章編集・Undo等を行った場合、古い情報からの更新は停止します。
その場合は画面を閉じ、メニューから取得し直してください。
文章以外の座標・サイズ・フォント等は変更しません。AUPの保存は自動では行いません。

文献の登録内容は、反映時に「作品名.references.json」へ保存します。
AUPが未保存ならAviUtlの作業フォルダの references.json を提案します。
「保存先を変更」で別ファイルを選べます。「文献ファイルを開く」で他の発表の登録内容も利用できます。
JSONの形式はキーと書誌情報の対応です（例は examples/citations/references.json）。
外部でJSONを書き換えた場合は、管理画面の「文献ファイルを再読み込み」を押してください。
別のファイルなら「文献ファイルを開く」で選びます。同じキーの書誌情報を一括で置き換え、
ファイルにない登録済みキーは保持します。その後「引用番号をAviUtlに反映」を押すと、
そのキーを使う全ての脚注・文献一覧が更新されます。読み込みだけではAviUtlは変更しません。
本文の \cite は番号だけ、\ref は書誌情報、\bibliography は引用済み文献の一覧を表示します。
JSONを読み込んでも、テキストオブジェクトの新規作成や手入力の文献との自動対応は行いません。
書誌情報の自動検索、BibTeXの取込み、本文の既存の数字から論文を推定する機能はありません。
既存の手入力の番号は、初回のみ対応する引用キーへ置き換えてください。

PPTX変換も同じ引用処理を使います。番号・脚注は編集可能な通常のテキストとして出力します。
管理用のコメントはPPTXには入りません。
PPTXへの出力フレームを絞っても、採番はシーン全体の初出順です。
旧版の更新済みEXOは埋め込み文献情報だけでも変換できます。
0.4.0の更新済みEXOは、CLIの --citation-state で引用管理ファイルを指定すると再採番できます。
AviUtlからの自動取得では作品名.citations.jsonを自動で読み込みます。
管理ファイルなしの場合、既に表示されている文章をそのままPPTXへ出力します。
未更新の引用キーを含むEXOは、同じフォルダの references.json またはCLIの --references で文献を指定します。
保存済みAUPからの自動取得では「作品名.references.json」があれば自動で利用します。

制限：現在のシーン単位で採番します。シーン参照を通した全体採番や常時監視は行いません。
非表示レイヤーを含め、取得されたテキストを対象にします。
中間点のある引用テキスト、同じオブジェクト内の複数のテキストフィルタ、引用文中のLuaスクリプトは未対応です。
表示する文章のUTF-16の文字数が1023を超える場合は停止します。
管理用データは外部保存するため、この上限を消費しません。
長い文章や文献一覧は複数のテキストに分けてください。
未登録キーや不正な引用記法では、近似変換を選んでも引用を省略して出力することはありません。

動作確認用の架空文献を使ったサンプル：examples/citations/demo.exo と demo.pptx。
EXOを拡張編集に読み込み、文献ファイルに examples/citations/references.json を指定すると試せます。
読み込みから並べ替えまでの手順は [サンプルの使い方](examples/citations/使い方.md) を参照してください。

## 対応範囲

- AviUtl 1の日本語EXO（CP932／UTF-8、UTF-16LEで格納されたテキスト）
- 「テキスト」＋「標準描画」の静止した通常文字
- 「画像ファイル」＋「標準描画」の静止画像
- 静止画像・対応する四角形の「クリッピング」（上・下・左・右、中心の位置を変更）
- 静止画像の「反転」の左右反転・上下反転。クリッピングとの適用順序も反映します。
- 「図形」＋「標準描画」の背景（type=0）・塗りつぶし四角形（type=2）。
  サイズ・縦横比・色・透明度・拡大率・回転・重なり順を反映します。
  背景は元の画面サイズ、四角形は指定サイズから配置します。
- X/Y、拡大率、回転、透明度、レイヤーの重なり順
- 文字列、改行、フォント、サイズ、色、太字、斜体、字間・行間
- 横書きの左／中央／右、上／中／下の基準位置
- 表示開始・終了に応じたスライドごとのオブジェクト切り替え
- 元の縦横比を維持したスライドサイズ

文字はWindowsのGDIで計測して配置します。
画像は元のピクセル寸法から配置します。透明度を反映するため内部ではPNGに変換しますが、
スライド全体を1枚の画像にはしません。
フォントは埋め込みません。表示するPCにも同じフォントが必要です。
EXOの文字色・図形色はRGBとして読み取ります。0.1.2で、赤と青が逆になる旧処理を修正しました。
0.1.2の図形・色の修正と0.1.3のクリッピング・左右／上下反転対応はPython側の変更です。
0.2.0のシーン自動取得は .auf 側も更新しています。
画像は元の全ピクセルをPPTXに保持し、PowerPointのトリミング・反転として保存します。
PowerPointで切り抜く範囲や反転を後から変更できます。
「中心の位置を変更」がOFFなら元画像の回転中心を保ち、非対称に切り抜いた位置を補正します。
対応する効果は画像・図形の生成後、標準描画より前に配置してください。

## 再現性と制限

**「未対応警告がない」ことは、AviUtlの見た目と完全一致することを意味しません。**

PowerPointとの描画方式の違いにより、文字の字幅、行高、ベースライン、アンチエイリアス、
フォントの代替・文字ごとのフォント補完などに差が残ります。
画面外にはみ出した文字や回転文字は、実際の画面との比較が必要です。

この試作版では以下を扱いません。

- 移動するトラックバー値、中間点、グループ、グループ制御
- 縦書き、テキスト制御タグ、タブ、文字ごとの表示・移動、スクロール
- スクリプト、動画、音声、円・多角形・枠線のみの図形・カスタム図形、シーン参照、カメラ制御
- 上のオブジェクトでクリッピング（EXOのclippingメタデータ）、文字のクリッピング・反転
- 輝度反転・色相反転・透明度反転、負のクリッピング量、画像全体を切り落とす設定
- 拡張描画、特殊な合成モード、Z座標、画像フィルタ
- 文字の縁取り・影（近似変換では通常文字になります）
- AviUtl本体側のフィルタ、EXOに保存されない情報・レイヤー状態
- PDF出力、フォント埋め込み

未対応設定を検出した場合、既定ではPPTXを作成せず、
保存先と同名の .report.json に理由を保存します。

「近似変換を許可する」を選ぶと、対応できない効果を省略し、
変換できないオブジェクトは除外してPPTXを作ります。
**この場合は文字・画像そのものが欠落することもあります。必ずレポートを確認してください。**
画像への自動フォールバックは実装していません。

## 間隔・座標・画像の指定

- フレーム番号は **EXO内で1始まり**。間隔30なら、1、31、61…を出力します。
- 範囲は開始・終了の両端を含みます。ただし終了フレームを強制追加はしません。
- EXOを書き出した範囲によって、元のAUPのフレーム番号とは異なる場合があります。
- 30fpsなら間隔30は1秒ですが、60fpsなら間隔60が1秒です。
- 既定の背景色は黒（000000）。必要なら白（FFFFFF）などに変更します。
- 画像の相対パスはEXOのあるフォルダを基準にします。
  AviUtlから自動取得した場合はAUPのフォルダ、未保存ならAviUtlの作業フォルダを基準にします。
- 「画像移動先」を指定すると、そのフォルダ直下の同名ファイルを使います。
  同じ名前の別画像を混在させないでください。
- PowerPointの幅は既定13.333333インチ、高さは元の縦横比から計算します。
- 一度の出力は最大2000枚です。空のフレームも空のスライドとして出力します。
- 既存のPPTX・レポートは上書きしません。再試行時は別の保存名を指定します。

## コマンドライン

このフォルダで実行します。

    .venv\Scripts\python.exe exo_to_pptx.py "作品.exo" -o "作品_editable.pptx" --interval 30

任意のフレームだけを出力：

    .venv\Scripts\python.exe exo_to_pptx.py "作品.exo" -o "選択.pptx" --frames 1,91,181

未対応設定の近似を許可：

    .venv\Scripts\python.exe exo_to_pptx.py "作品.exo" -o "近似.pptx" --allow-approx

画像を移動した場合：

    .venv\Scripts\python.exe exo_to_pptx.py "作品.exo" -o "再配置.pptx" --asset-dir "E:\画像"

その他： --start、--end、--background、--slide-width。
--frames は間隔と範囲の指定より優先されます。

## 別の環境への導入

WindowsとPython 3.10以降（tkinterを含む通常のインストール）が必要です。
新しい配置先で setup.cmd を実行し、その後 launch.cmd を実行します。
依存関係は requirements.txt に記載し、このフォルダの .venv にインストールします。
この作業環境のPythonは3.11.9です。仮想環境の別PCへのコピーは避けてください。

GUIの初期化に失敗する環境のため、この作業フォルダには元のPythonと同じTcl/Tkを
.runtime/tcl にコピーしてあります。元のPythonのファイルは変更していません。
通常のTk初期化が失敗した場合のみ、このローカルコピーを利用します。
別バージョンのPythonに移す場合は、対応する通常のTcl/Tk環境を用意してください。

AviUtl起動用プラグインはビルド済みで、x86 DLLとGetFilterTableエクスポートを確認しました。

PowerPoint本体での描画確認はCOM起動時にログオンセッションエラー（0x80070520）が発生したため、
この環境では実施できていません。AviUtlの実画面との比較も未実施です。
examples/sample.pptx を手元のPowerPointで確認してください。

PowerPointを使った描画確認を手動で行う場合：

    powershell -NoProfile -ExecutionPolicy Bypass -File verify_powerpoint.ps1 -InputPptx examples\sample.pptx -OutputFolder examples\rendered

入力PPTXは読み取り専用で開き、PNGと文字抽出結果を新しいフォルダに保存します。

## 起動プラグインの再ビルド

Visual StudioのC++ x86ビルドツールとWindows SDKが必要です。

    plugin\build.cmd

出力は plugin/build/EditablePptxExport.auf と plugin/build/CitationManager.auf です。
ビルド成功時は、このフォルダ直下の両方の .auf も更新します。
既存の AviUtl1/IntervalPngExport/sdk/filter.h を読み取り専用で参照しています。
既存プロジェクト・ソリューションは変更しません。

## アルティメットのテキスト編集で自動折り返し

この環境の text_editor.aua は、編集欄の横スクロールを無効にする修正版を準備しました。
ウィンドウ幅に合わせて表示上だけ折り返し、実際のテキストには改行を追加しません。
引用の管理画面の文章・プレビュー欄も表示上の折り返しを行います。
修正版作成用の patch_ultimate_wrap.py は、元DLLを変更せず別の出力ファイルを作ります。
導入後はAviUtlの再起動が必要です。アルティメットを更新すると元に戻る場合があります。
元のDLLは .verification/ultimate-wrap/text_editor.original.aua に保管します。
対象が未知の構造の場合、修正版の作成を停止します。
[アルティメットの公式テキスト編集説明](https://hebiiro.github.io/anti.aviutl.ultimate.plugin/contents/addin/text_editor.html)

0.4.0では計50件のテストが成功しました。
独立したAviUtl環境で、管理コメントを含まない本文・脚注への更新、
外部保存した引用キーを使った並べ替え後の再採番、Ctrl+Zによる一括取り消しを確認しました。
折り返し修正版についても、編集コントロールの複数行表示と文字列が変化しないことを確認しました。
